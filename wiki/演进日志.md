## [2026-11-08] experiment | 思考强度缓存受控运行结果

- 更正上一条 config 日志：用户已在根目录 `.env` 填入真实 `DEEPSEEK_API_KEY`，因此“只有占位项”“未发真实请求”已过时；密钥未打印、未写入结果。
- 原计划用于检查缺失密钥路径的单请求，因 `.env` 已配置而实际发出 1 次冷启动请求：输入 1990、缓存命中 0、输出 2；记录在 [single-warmup.json](../experiments/思考强度缓存验证/results/effort-cache-20261108-011432-single-warmup.json)，不计入下面的 5 次对照序列。
- 完整运行 `high → high → low → low → high`，固定 12,000 字符前缀，间隔 5 秒；原始记录见 [effort-cache-20261108-011514.json](../experiments/思考强度缓存验证/results/effort-cache-20261108-011514.json)。
- 结果：high 暖场 1989 输入 / 0 命中 / 0.00%；high 对照 197 输入 / 1792 命中 / 90.10%；low 切换 1989 / 0 / 0.00%；low 稳定 197 / 1792 / 90.10%；high 回切 197 / 1792 / 90.10%。
- 结论：支持“effort 进入缓存前缀、切换 effort 使前缀冷启动”；不同 effort 的前缀缓存可以并存，回切 high 能复用旧前缀。仅覆盖 `deepseek-flash` 官方 Messages 端点单次运行。
- 已回填 [概念页](concepts/API适配器与模型输入语义.md)、[模板来源页](sources/DeepSeek-V4.1-Flash对话模板.md)、[实验页](explorations/思考强度切换缓存实验.md) 与 [知识导航](知识导航.md)。
